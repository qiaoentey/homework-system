# Daycare 分院点名与学生管理系统设计

## 目标

在现有 STP 点名系统的功能基础上制作一个更简单、速度更快的优化版。用户登录后先选择分院，再选择老师，系统只加载该老师的学生名单。同时加入 Enrol 学生与停补学生功能。

本次不统一或改造 Lark Base，也不增加额外的数据看板。

## 页面流程

1. 用户登录系统。
2. 首页只显示三个大型分院按钮：`MK`、`STP`、`WS`。
3. 用户选择分院后，只显示该分院的老师班级。
4. 用户选择老师班级后，只加载该老师名下、状态为“在读”的学生。
5. 页面提供返回老师选择和返回分院选择的入口，避免混入其他分院名单。

入口继续采用用户选定的第一套视觉方案：现有系统的蓝白风格、三个纵向大按钮、标题“请选择分院”，副标题“进入后只显示该分院名单”。

## Enrol 学生

老师名单页面提供 `Enrol 学生` 按钮。表单包含：

1. 学生姓名
2. 年级
3. 老师班级
4. 与现有系统相同的学生个人资料栏

表单从当前分院进入时，老师班级只能选择该分院的老师。保存成功后：

- 新学生状态为“在读”。
- 学生立即出现在对应老师的点名名单。
- 学生不会出现在其他老师或其他分院名单。
- 系统显示明确的保存成功提示。

学生姓名、年级和老师班级为必填。缺少必填资料、老师班级不属于当前分院或保存失败时，不创建学生，并显示具体错误信息。

## 停补学生

老师名单页面提供 `停补学生` 按钮。表单只包含：

1. 学生姓名
2. 年级
3. 老师班级

提交前显示学生身份与老师班级，让用户确认停补对象。确认后：

- 学生状态从“在读”改为“停补”。
- 学生立即从日常点名名单隐藏。
- 学生个人资料和所有历史点名记录继续保留。
- 不删除学生记录。

系统保留恢复功能，可将停补学生重新设为“在读”，恢复后立即回到原老师的点名名单。

如果姓名、年级和老师班级无法唯一匹配学生，系统不得自行停补任何学生，而是要求用户选择正确的学生。

## 名单与点名数据流

- 分院选择决定可见的老师班级。
- 老师班级选择决定可见的学生。
- 点名页面只请求并渲染选定分院、选定老师且状态为“在读”的学生。
- Enrol、停补和恢复操作完成后，只刷新当前老师名单。
- 每条学生记录使用稳定的内部学生编号，不能只依靠姓名识别，以免同名学生互相覆盖。
- 历史点名记录继续关联内部学生编号；改年级、换老师或停补都不会破坏旧记录。

## 性能与已发现问题修正

现有系统会同时渲染大量学生卡片和按钮，移动页面过长，可能造成卡顿。优化版必须：

- 选择老师后才加载该老师名单。
- 不在页面中同时渲染桌面版和手机版的重复内容。
- 搜索、年级筛选和名单分段只处理当前老师的学生。
- 大名单采用分页、分段加载或虚拟列表，避免一次建立数千个按钮节点。
- 加载名单时显示加载状态；失败时提供重试按钮。

现有学生搜索还有一个风险：无结果时仍保留上一位学生资料并允许保存。优化版必须在无匹配结果时：

- 清空上一位学生选择。
- 隐藏或禁用保存按钮。
- 明确显示“找不到学生”。

同时将页面中的“接生”文字检查并修正为正确的“接送”用语。

## 权限与安全

- 前端选择分院只是界面状态，后端仍须验证分院和老师班级关系。
- 新增、停补、恢复和编辑学生资料都需要已登录用户。
- 提交按钮在请求进行中暂时禁用，防止重复新增或重复停补。
- 失败操作不能留下半完成记录。

## 验收标准

1. 登录后的第一屏只显示 `MK`、`STP`、`WS`。
2. 选择分院后只显示该分院老师，选择老师后只显示其在读学生。
3. MK、WS 与 STP 名单不会互相混入。
4. `MK QIAO EN` 不包含基础班。
5. Enrol 学生保存后立即进入正确老师名单，个人资料可以正常查看和编辑。
6. 停补学生立即从点名名单隐藏，但历史点名与个人资料仍可查。
7. 恢复学生后会重新出现在原老师名单。
8. 无搜索结果时不能覆盖上一位学生资料。
9. 手机与电脑都能顺畅完成分院选择、老师选择、点名、Enrol 和停补。
10. 页面加载失败、保存失败和重复提交都有清楚提示，不会造成重复或错误资料。

## 交付范围

优化版以现有线上系统的功能和视觉作为参考，在当前项目中实现并完成浏览器测试。交付时提供可使用的网站入口。现有 Render 网站是否直接替换，取决于实施阶段能否取得原项目及其部署权限；若没有权限，则发布为新的优化版网站地址。
