# 出席与缺席记录设计

## 目标

让老师在当前分院、当前老师班级内查看每天的点名结果。点名仍然在学生卡片上即时自动保存，不增加“确认”或“提交”步骤。

## 记录定义

- “出席”只对应现有的“到”（`arrive`）点名状态。
- “缺席”只对应现有的“缺席”（`absent`）点名状态。
- “未点名”表示学生当天既没有“到”，也没有“缺席”。
- “冲、餐、功、补、复、回、KOKO”等其他状态继续独立保存，但不计入出席或缺席名单。
- 学生卡片不再显示“接”（`pickup`）按钮。以前保存的“接”记录不删除，后台继续兼容旧资料，但老师不能再新增或修改“接”状态。
- 已保存的历史出席与缺席事件继续使用现有 `attendance_events` 数据，不搬移或删除旧记录。

## 点名互斥规则

- 老师开启“到”时，系统在同一次后台操作中关闭该学生当天的“缺席”。
- 老师开启“缺席”时，系统在同一次后台操作中关闭该学生当天的“到”。
- 老师关闭当前状态时，只关闭所按的状态，不自动开启另一个状态。
- 前端同步更新两个按钮，避免等待刷新时显示旧状态。
- 如果旧数据中同一天同时存在“到”和“缺席”，记录接口不隐藏冲突；该学生显示在“需要确认”提示内，老师重新点名后冲突自动消失。

## 老师界面

在现有“Enrol 学生、停补学生、恢复学生”按钮旁增加“点名记录”。点击后打开简单对话框：

1. 顶部显示当前老师班级名称。
2. 日期默认今天，可选择今天或更早日期，不允许未来日期。
3. 显示出席、缺席、未点名三个数字。
4. 下方分三栏列出学生姓名和年级；手机上改为单栏排列。
5. 只有旧数据发生冲突时，额外显示“需要确认”警示名单。
6. 切换日期后自动载入，不需要额外按查询。
7. 载入失败时只在对话框内显示错误和“重新载入”，不影响当前点名页面。

本次不加入月历、逐个学生长期统计、Excel 下载或打印，保持老师操作简单。

## 数据接口

新增只读接口：

`GET /api/attendance-records?branch=<branch>&group=<group>&date=YYYY-MM-DD`

响应包含：

- `date`
- `present`：学生 `id`、`name`、`grade`
- `absent`：学生 `id`、`name`、`grade`
- `unmarked`：当前在读名单中未有“到”或“缺席”的学生
- `conflicts`：同时有“到”和“缺席”的旧冲突记录
- `counts`：以上各组人数

接口必须沿用现有分院与老师班级范围验证。出席和缺席名单包含该班当天已有记录的学生，即使学生后来停补，也不会从历史的已保存记录消失；未点名名单以当前在读名单为准。

## 后台一致性

- Sites Worker 与 Express 后端提供相同接口和相同响应。
- 更新“到/缺席”时，Worker 使用 D1 batch，Express 使用数据库 transaction，确保互斥更新不会只完成一半。
- 无需新增数据库表或迁移；现有唯一键 `(student_id, attendance_date, event_code)` 继续使用。
- 除移除“接”按钮和新增“到/缺席”互斥外，原有点名、统计、清除今日和重试行为保持不变。

## 测试与验收

- API 测试：范围验证、日期验证、出席/缺席/未点名分类、停补后的历史保留、旧冲突返回。
- 互斥测试：开启“到”关闭“缺席”，开启“缺席”关闭“到”，关闭状态不反向开启。
- 客户端测试：记录入口、默认日期、切换日期、三组名单、空名单、冲突、错误重试。
- 点名按钮测试：学生卡片不显示“接”，其他九个按钮保持原有顺序与行为。
- 浏览器测试：电脑和手机都能打开记录、查看当前班级、切换日期；原点名与生命周期流程继续通过。
- 发布后检查原网址健康状态，老师继续使用现有链接。
