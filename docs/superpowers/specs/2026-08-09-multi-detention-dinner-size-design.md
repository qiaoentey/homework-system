# 留堂多选与晚餐份量设计

## 目标

让老师可为同一名学生同时选择「听写留堂」和「功课留堂」，并在每天的晚餐资料中记录大份或小份，同时完整兼容已经保存的学生资料。

## 方案选择

考虑过三种做法：为每项留堂新增独立资料字段、把多选存成 JSON 字符串、或沿用现有 `detentionType` 字段并使用稳定分隔格式。采用第三种，因为改动最小、不需要数据库迁移，而且旧的单选值可直接读取。

晚餐采用每天选择份量，不采用一个全周共用份量。这样学生可以在不同星期选择不同份量，也与现有星期一至星期五的操作方式一致。

## 留堂操作

- 将现有单选下拉改成三个可点按的复选框：`听写留堂`、`功课留堂`、`不可以留堂`。
- `听写留堂`与`功课留堂`可以同时选择。
- 选择`不可以留堂`时自动清除另外两项；已选择`不可以留堂`后再选择另外两项时自动清除`不可以留堂`。
- 多个值继续保存在现有 `detentionType` 字符串字段，以 `|` 分隔。旧的单项值仍按原样显示为已选择。
- 留堂选择继续使用现有学生资料保存按钮，不增加额外操作。

## 晚餐操作

- 保留总开关「是否需要晚餐」。只有选择`需要`时才显示星期一至星期五。
- 每天的选项改成`不需要`、`小`、`大`。
- 第一次选择需要晚餐时，未填写的星期仍自动设为`不需要`。
- 旧资料中的每日值`需要`保留为「需要（未选大小）」选项，避免资料被静默修改。
- 改成不需要晚餐时，继续清空五天资料。

## 名单标签

晚餐标签按份量分组显示星期，例如：`晚餐 · 小：周一、三 · 大：周二`。旧的`需要`资料显示为`未选大小：周五`，提醒老师补选而不隐藏旧资料。

## 数据与错误处理

沿用学生 `profile` JSON 及既有字段，不新增数据库表或栏位。服务器、Sites Worker 和旧数据合同无需扩充。保存失败及重试继续沿用现有行为。

## 验证

- 留堂双选、互斥规则与旧单值回填。
- 晚餐大/小份、首次默认不需要、关闭后清空与旧`需要`兼容。
- 名单标签按份量及星期显示。
- 学生资料保存、Enrol、服务器、Sites Worker、电脑及手机流程通过。
