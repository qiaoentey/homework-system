# 学生晚餐资料设计

## 目标

在现有「学生资料」与「Enrol 学生」表格加入简单的晚餐选择，让老师先选择学生是否需要晚餐；只有选择「需要」时，才显示星期一至星期五的每日选择。

## 交互设计

- 新增下拉选项「是否需要晚餐」，可选择「请选择」「不需要」「需要」。
- 选择「需要」后，立即展开星期一至星期五五个下拉选项。
- 每天只有「需要」与「不需要」两个选择；第一次展开时，尚未填写的日期自动设为「不需要」。
- 改成「不需要」或「请选择」时，隐藏并清空五天的选择，避免隐藏资料继续被误用。
- 晚餐区放在学生资料基本资料之后、特别留校时间之前；手机上沿用现有自适应网格，保持可点按尺寸。

## 数据设计

沿用学生现有的 `profile` JSON，不新增数据库表或栏位。加入六个字符串字段：

- `dinnerRequired`
- `dinnerMonday`
- `dinnerTuesday`
- `dinnerWednesday`
- `dinnerThursday`
- `dinnerFriday`

旧学生资料缺少这些字段时，前端统一视为空白，因此旧资料可以继续正常打开和保存。新 enrol 与资料更新请求会包含完整字段；服务器与 Sites Worker 使用同一字段白名单。

## 保存与错误处理

- 使用现有「保存学生资料」与「保存学生」流程，不增加额外按钮。
- 保存成功、失败与重试提示沿用现有行为。
- 更换学生时，由该学生已保存的资料重新决定是否展开星期选项，不保留上一位学生的晚餐状态。

## 测试范围

- 未选择「需要」时，不显示星期选项。
- 选择「需要」时，显示星期一至星期五并把空白日期设为「不需要」。
- 每日选择会包含在资料保存请求中，重新载入后仍显示。
- 选择「不需要」会隐藏并清空每日选择。
- Enrol、资料 API、Sites Worker、桌面与手机浏览器流程继续通过。
