# 当天托育 Dashboard 设计

## 目标

在现有点名系统加入一个所有已授权 Google 帐号都能查看的 Dashboard。Dashboard 汇总 MK、STP、WS 每个托育班当天的点名结果，并可展开查看每位学生当天的主要状态。当前班级统计页与 Dashboard 必须采用同一套统计口径。

## 范围

- Dashboard 只显示当天数据，不加入历史趋势或图表。
- 登录后的分院选择页增加明显的 `Dashboard` 入口。
- Dashboard 顶部显示当天日期，并提供 `全部`、`MK`、`STP`、`WS` 分院筛选。
- 每个老师托育班显示一张状态卡。
- 状态卡显示 `应到`、`已到`、`还没有`、`缺席`、`KOKO`、`未点`。
- 点击班级卡片后展开全部在读学生，并在名字旁显示当天主要状态。
- 所有已授权的 Google 帐号都可以查看全部 Dashboard 数据。
- Dashboard 提供手动刷新；一次班级载入失败不得影响其他班级。

## 统一统计口径

学生每天只有一个主要状态：`已到`、`缺席`、`KOKO` 或 `未点`。老师选择新的主要状态时自动替换旧的主要状态。

- `应到`：当前班级所有在读学生。
- `已到`：主要状态是 `已到` 的学生。
- `缺席`：主要状态是 `缺席` 的学生。
- `KOKO`：主要状态是 `KOKO` 的学生。
- `未点`：尚未选择当天主要状态的学生。
- `还没有`：`KOKO + 未点`。

必须满足：`应到 = 已到 + 缺席 + KOKO + 未点`。

当前班级统计页和 Dashboard 必须复用同一个统计计算单元，不得在两个页面各自实现一份公式。

## 点名画面

- 恢复 `KOKO` 点名按钮。
- 主要状态按钮顺序固定为：`到`、`缺席`、`KOKO`。
- 其他独立日常事件继续显示：`冲`、`餐`、`功`、`补`。
- `到`、`缺席`、`KOKO` 互斥；选择其中一个会移除另外两个。
- 当前班级统计文字统一为：`应到`、`已到`、`还没有`、`缺席`、`KOKO`、`未点`。

## Dashboard 页面

采用用户选择的 A 版布局：每班状态卡加可展开学生状态。

- 卡片标题显示分院和老师班级。
- 六个统计数字在卡片顶部以紧凑网格显示。
- 学生列表默认收起，点击卡片展开，避免手机页面过长。
- 学生状态颜色：已到绿色、缺席红色、KOKO 紫色、未点灰色。
- 卡片独立显示载入中、失败与重试状态；其他卡片保持可用。
- 页面自动载入当天数据，完成点名后重新进入或点击刷新即可看到最新结果。

## 数据接口与边界

- 后端新增一个当天 Dashboard 读取接口，一次返回所有分院和托育班的统计及学生状态，避免浏览器逐班发出大量请求。
- 接口只返回在目录中存在的分院和老师班级，并只计算在读学生。
- 现有当前班级汇总接口改为调用相同的统计函数。
- 学生新增、停补、恢复后，下一次读取会使用最新在读名单重新计算 `应到`。
- Dashboard 与当前班级统计都以马来西亚本地当天日期作为默认日期。

## 错误处理

- 全页读取失败时显示重试按钮，不显示过期数字。
- 单个班级资料异常时，该班显示失败状态，其余班级继续显示。
- 点名写入失败时维持现有回滚与重试行为，Dashboard 不提前显示未保存状态。
- 如果发现旧资料同时拥有多个主要状态，读取时按 `缺席 > 已到 > KOKO > 未点` 显示，并在写入下一次主要状态时清理冲突。

## 验证

- 单元测试统一统计公式、互斥状态与旧冲突兼容。
- 服务端测试 Dashboard 的分院/班级边界、在读名单、六项数字和学生状态。
- 客户端测试 Dashboard 入口、分院筛选、卡片展开、颜色标签、刷新与错误重试。
- 端到端测试确认当前班级统计与 Dashboard 数字一致。
- 在电脑和手机尺寸分别验证所有分院。

## 非目标

- 本次不加入历史日期选择、趋势图、出席率目标、下载或打印。
- 本次不新增管理层权限；所有已授权 Google 帐号均可查看。
