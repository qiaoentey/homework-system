# 缺席原因设计

## 目标

老师在点名页面第一次点击“缺席”时必须选择原因。原因包括“生病、旅行、校外比赛、家事、其他”；选择“其他”时必须填写说明。保存后的原因要在学生卡片、Dashboard 和点名记录中显示，并跟随日期永久保存。

## 推荐交互

- 未缺席的学生点击“缺席”后打开一个轻量对话框，不先改变学生状态。
- 对话框提供五个单选项。选择“其他”后显示一个最多 100 字的输入框；空白内容不能保存。
- 点击“确认缺席”后，学生才变成缺席并保存原因；关闭或取消不改变点名结果。
- 已缺席的学生再次点击“缺席”时直接取消缺席，保留现有的一键切换习惯。
- 点“到”仍会自动取消缺席；点名按钮保存失败时恢复到保存前的状态和原因，并允许重试。

## 数据与 API

- `attendance_events` 增加可为空的 `absence_reason` 文本字段，旧记录保持 `NULL` 并继续可读。
- `PUT /api/students/:id/attendance/:date/:eventCode`：
  - `absent + active=true` 必须提供去除首尾空白后长度为 1–100 的 `reason`。
  - `absent + active=false` 以及其他点名项目只接受 `{ active }`。
  - 取消缺席或改点“到”时清空旧缺席原因，避免无效原因继续显示。
- 名单接口的点名项目返回 `absenceReason`；Dashboard 和点名记录中的缺席学生同样返回 `absenceReason`。
- 固定原因按原文保存；“其他”保存老师输入的实际内容，显示时统一为“其他：填写内容”。

## 显示规则

- 学生卡片：缺席按钮下方显示红色“缺席原因：…”标签。
- Dashboard：学生当天状态下方显示“缺席原因：…”。
- 点名记录：缺席名单的年级旁显示“缺席原因：…”。
- 旧的无原因缺席记录只显示“缺席”，不伪造原因，也不会造成页面错误。

## 验证

- 客户端测试覆盖固定原因、其他原因必填、取消弹窗、再次点击取消、保存失败重试与旧记录兼容。
- PostgreSQL 与 Sites D1 测试覆盖字段迁移、请求验证、写入、读取、Dashboard 和历史记录。
- 桌面与手机端浏览器测试覆盖选择原因、保存后显示及 Dashboard 显示。
